[SIZE=5][B]Bugs / notes[/B][/SIZE]


[LIST]
[*]Google SetupWizard is [B]temporarily disabled[/B] while its page lock/unlock bug is fixed. First boot goes straight to the launcher; sign in through Play Store.
[*][B]Dolby Atmos removed[/B] from this and all future builds. The A42 5G blob set has no Dolby effect library and no profiles, so the switch did nothing. AudioFX is included instead.
[*]Play services ships as a priv-app APK fallback because the GMS APEX does not activate on this device.
[*]fs-verity on f2fs is fixed in the next kernel build. Current builds log harmless [ICODE]Failed to verity-protect ...[/ICODE] lines.
[*]Do [B]not[/B] wipe [ICODE]/metadata[/ICODE]: the factory key cannot be regenerated and the device will not boot without the patched fstab.
[*]Banking apps may still apply their own root or bootloader checks.
[*]KernelSU-Next is built into the kernel; if an app refuses to run because of root, hide it with your usual modules or use a boot image built without KernelSU-Next. No non-root boot image is shipped here.
[*]Unofficial build: there is no update server, so no OTA updates, and no official maintainer support. Don't ask for ETAs.
[*]Anything else: report it with a logcat and, for boot issues, [ICODE]last_kmsg[/ICODE]/[ICODE]dmesg[/ICODE].
[/LIST]

This is an unofficial build, expect some imperfections. If you have any issues/bugs, please provide logcat or last_kmsg/etc.


[SIZE=5][B]Installation[/B][/SIZE]


Flash with TWRP or with the Lineage recovery inside the zip ([ICODE]recovery.img[/ICODE]). Both work.

1. Boot into recovery
2. Format Data, but only if you are coming from a build signed with different keys
3. Flash the ROM zip
4. If you want Google apps, flash them now, in the same session, before the first boot
5. Reboot to system

Once you are on an Infinity-X build signed with these keys, later builds can be dirty flashed without wiping, from either recovery.


[SIZE=4][B]Google apps on VANILLA[/B][/SIZE]


The ROM ships without Google apps unless you pick the GAPPS variant. For vanilla builds use [B]BiTGApps Nano for Android 17 arm64[/B]: [URL]https://bitgapps.io[/URL] — Nano → ARM64 → Android 17.0. Flash it straight after the ROM and before the phone boots for the first time. Don't use a package built for another Android version, and a clean flash is required if you add GApps after the first boot.

Do not use BiTGApps' debloat option: it strips stock apps like Messaging, and SMS/MMS stop working until you put an APK back by hand.

[SIZE=5][B]Root manager (KernelSU-Next)[/B][/SIZE]


The kernel ships KernelSU-Next with driver [B]uapi 6[/B] ([ICODE]v3.4.0-legacy-24-gb933b1f7 (33318-6)[/ICODE]). The official KernelSU-Next [B]3.4.2[/B] manager is uapi 5 ([ICODE]33355-5[/ICODE]) and refuses to work with it, reporting that the manager is too low and must be version 6 or higher. No official uapi-6 manager has been released yet, so install the CI build from the [ICODE]dev[/ICODE] branch:

[LIST]
[*][B]APK[/B]: [ICODE]KernelSU_Next_v3.4.2-198-g7ccf6147_33553-release.apk[/ICODE] (versionCode [ICODE]33553[/ICODE], manager uapi 6)

[*][B]SHA-256[/B]: [ICODE]3860d41c86ff30dd31af815f30032de03ffd71e775a44311ef319db539a927d7[/ICODE]
[/LIST]

[SIZE=5][B]SELinux — what enforcing actually took[/B][/SIZE]


There is no usable Samsung vendor policy for AOSP on this platform, so enforcing was never a one-line flag. The device policy in [ICODE]sm7225-common[/ICODE] is written and maintained here: [B]71 [ICODE].te[/ICODE] files, 368 [ICODE]allow[/ICODE] rules, 39 [ICODE]dontaudit[/ICODE] rules, 108 [ICODE]file_contexts[/ICODE] and 104 [ICODE]genfs_contexts[/ICODE] entries[/B], roughly 960 lines of policy and labels that this port carries itself.

[LIST]
[*]Every Samsung blob got a domain and a label instead of running as [ICODE]unlabeled[/ICODE]: radio ([ICODE]rild[/ICODE], [ICODE]sehradiomanager[/ICODE], [ICODE]secril_config_svc[/ICODE], plus the [ICODE]imsd[/ICODE]/[ICODE]imsd2[/ICODE] channels), UDFPS/fingerprint, [ICODE]tee[/ICODE], keymaster/gatekeeper, NFC, camera, audio, display and composer, sensors, power, thermal, WiFi hostapd/supplicant, Bluetooth, DRM/Widevine, health, fastcharge, LiveDisplay, vold, init and macloader.
[*]The rules were built deny by deny: boot with enforcing on, read the AVCs, find the exact domain and object, add the narrowest allow that lets the blob do its job, boot again. Nothing is left [ICODE]permissive[/ICODE] and there is no catch-all allow hiding the log.
[*][ICODE]user[/ICODE] builds are stricter than [ICODE]userdebug[/ICODE], and that broke things late: [ICODE]crash_dump[/ICODE] could not ptrace [ICODE]vold[/ICODE], [ICODE]system_server[/ICODE] could not read [ICODE]binderfs_logs_transactions[/ICODE], and SystemUI's [ICODE]ro.usb.uvc.enabled[/ICODE] read needed silencing rather than opening the property up.
[*]Vendor properties, service and hwservice contexts needed fixing as well, otherwise init and HAL registration hit [ICODE]property_service[/ICODE] and [ICODE]hwservicemanager[/ICODE] denials before the launcher ever appears.
[*]Still being cleaned in the next build: [ICODE]rild[/ICODE] on [ICODE]vendor_diag_device[/ICODE] and the NFC HAL on [ICODE]default_prop[/ICODE] get explicit, narrow allows for the two remaining repeat denials.
[/LIST]

The result is SELinux enforcing from first boot with no permissive domains, and every denial left in the log has been triaged as vendor noise or fixed.
